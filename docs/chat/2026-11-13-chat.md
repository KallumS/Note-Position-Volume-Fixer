I've built a tool that does this and works with any library and any DAW, including Ableton, Cubase and REAPER. It's one web page that runs offline in your browser, and no files leave your computer. It has only been tested against a made-up library with known delays. I couldn't try it in a real DAW or with Berlin Strings here.

**What I found.** Nothing existing measures delay per note (each key at each velocity), and nothing fixes volume.
- Negative track delay gives one value per track.
- Cubase 15's Attack Compensation and Dorico's expression maps work per articulation, with values you type in. Forum reports say Cubase's version has sign problems and legato bugs.
- The closest product is NTD Engine (about $39). It measures and switches delays per articulation and dynamic, but it doesn't mention volume. It's a VST3/AU MIDI effect, which Ableton can't host — I couldn't confirm this with the maker.
- The community delay spreadsheet is disputed: one user found almost none of its Berlin values accurate enough.

**How it works.**
- **From the part's own render:** export the MIDI clip, render the same clip, and drop both on the page. It finds where each note is actually heard and how loud it is. You get back a MIDI file with every note moved so its sound lands on the grid, and velocity (or CC11) changed where a note is too loud or too quiet.
- **From a learned profile (more accurate):** once per patch, the page gives you a test MIDI file that plays every key at several velocities. You render it and drop the audio back in. After that, any part on that patch only needs its MIDI file, with no rendering.
- Keyswitches stay ahead of the notes they switch. If you choose a track's notes, other tracks are left alone. A "Played at … BPM" field covers Live and Cubase ignoring a MIDI file's tempo on import.

**Accuracy on the test library:**

| Part | Timing error after fixing (typical / worst) |
| --- | --- |
| Staccato line, from its render | about 2 ms / 10 ms |
| Legato, from its render | about 6 ms / 12 ms |
| Anything from a learned profile (chords and legato included) | under 1 ms / 2 ms |

Uneven loudness drops from about 3 dB to under 0.5 dB.

**Limits from a render alone:**
- Chords are moved as one attack. A profile also lines up the notes inside a chord.
- Very fast passages whose notes differ by more than half the gap between notes can't be untangled.
- Round robins may play a different sample next time, so use "Each key" or a profile.
- If velocities change, render the fixed part and check it again, because a new velocity can play a sample with a different delay.

For Ableton, the next step I'd suggest is a Max for Live device that applies a learned profile to a clip in place, so there's no exporting. I couldn't build it here because I can't run Max to test it.

### Claude

Yes, it's feasible. It's the profile I already built, measured automatically instead of you rendering a test file per patch. The measuring code doesn't depend on the browser, so any of these could reuse it as is. What's hard isn't playing notes or measuring them. It's switching patches without you, and how long the playing takes.

**How long it takes.** Every key at 4 velocities, 2 takes each, about a second per note, is roughly 8 minutes per articulation. 20 instruments × 8 articulations is about 21 hours. That's fine overnight and unattended, but it isn't quick. Short articulations can be played faster, and keys or velocities can be thinned out. Skipping keys would miss single faulty notes, though.

**Three ways to do it:**

| | Max for Live (in Ableton) | REAPER script | Standalone program that loads your plugins |
| --- | --- | --- | --- |
| Plays in real time or faster | Real time | Faster than real time | Faster than real time |
| Changes articulation (keyswitch, CC, program change) | Yes | Yes | Yes |
| Changes instrument or patch | Through an Instrument Rack: one chain per patch, stepped by the Chain Selector | Yes, by loading saved plugin presets or FX chains | Only presets you save in it first; Kontakt and SINE can't be told to load a patch by a program |
| Timing reference | Needs checking: device and plugin delay compensation | Exact | Exact |
| Can I build and test it here? | Can't test it: needs Max and Live | Can't test it: needs REAPER | Builds here, but can't be tested with your libraries |
| Size of job | Medium | Small to medium | Large |

**What I'd recommend for you:** a Max for Live **Profiler** device on a track with an Instrument Rack, one chain per patch.
- For each chain, it plays the test notes through each articulation from a list you give it (keyswitch, CC or program change).
- It records the rack's output and measures it with the same code as the page. Max 9 runs plain JavaScript.
- It saves one profile per patch and articulation, named after the chain, which the page can open.
- A second small device, **Apply Profile**, would fix a selected clip in place. That removes the export and import round trip completely.

Caveats:
- **Ableton doesn't time-stamp audio against MIDI for a device.** The first job would be confirming the timing. Including a known reference with no delay in each run would let the device correct for it.
- **I'm not certain Live passes MIDI channels from a device on to a plugin.** That matters if you'd rather drive a Kontakt multi with one patch per channel instead of a rack.
- **Profiles only help if the fix knows which articulation each note uses.** With one track per articulation that's automatic. With keyswitch tracks, the fix would read the keyswitches to choose the profile.

If you use REAPER as well, it's the most hands-off option: it can load each patch from a saved preset and render offline. The profiles are just files, so ones measured in REAPER work in Ableton too.

To pick the route, it would help to know:
1. Do you have Live Suite (or Max for Live)?
2. Are your libraries mostly in Kontakt, SINE, Spitfire's player, or a mix?
3. Is your template one track per articulation, or keyswitches on one track?
4. Do you own REAPER?

I've built two REAPER scripts that do this unattended: one plays through your libraries and measures them, the other fixes your MIDI from those measurements. They've only been run against a pretend REAPER and a made-up library here, never in real REAPER or with your players.

**Note Fixer - Measure Libraries**
1. Load a patch on any track, select the track and press **Add Instrument From Selected Track**. The script remembers the plugin with that patch loaded.
2. List the articulations and how each is chosen: keyswitch, CC (Spitfire's UACC is CC32), program change or MIDI channel. Set whether its dynamics follow velocity (short notes) or CC1, the mod wheel (long notes).
3. Press **Measure All**. Each instrument goes on a new track, as you suggested. Reverb and other effects after the instrument are switched off. It waits for samples to load, then plays every key at your chosen levels, renders offline and measures. The track is then removed.
4. You get one profile per articulation. If a render comes back with notes missing (samples still loading), it waits and tries once more. A stopped run carries on where it left off.

The default range is C0–C6, 4 levels, 2 takes each, which is about 10 minutes of audio per articulation. REAPER renders that faster than real time. Measuring took about 26 seconds per 300 notes here, so roughly 40 seconds per articulation.

**Note Fixer - Fix Selected Items**
- It picks each track's instrument from the track name.
- Each note uses the profile of whichever articulation its keyswitch, CC, program change or channel chose.
- It moves the note by that key and dynamic's own delay.
- It lowers or raises velocity for keys that are too loud or quiet, or writes CC11 for long notes.
- If a note has to move before the start of its item, the item is extended. One Undo reverts the whole fix.

The browser page can open these profiles too.

**What the tests show:**
- The REAPER version and the browser version measure the same audio to within 0.5 ms and 0.3 dB.
- Both windows ran end to end against a stand-in REAPER that produces real audio from the made-up library. That covered adding an instrument, a render that came back silent and was retried, two articulations 40 ms apart, fixing a part that switches between them, and cleaning up afterwards.
- I broke the code on purpose four ways, and the tests caught each one.
- **Open questions only real REAPER can answer:**
  - whether each player loads its patch from the copied settings (SINE and Spitfire content, Kontakt multis);
  - whether REAPER's offline render waits for samples still streaming from disk;
  - how fast it renders.

  The safest first test is one Kontakt patch, two articulations, a short key range.

**Install:** you need ReaImGui, installed with ReaPack. The ReaPack link only works once this branch is merged into `main`. Until then, copy the `reaper` folder into REAPER's Scripts folder and load both scripts from the Actions list.

As before, this has only been tested against the stand-in REAPER, not real REAPER or your libraries.

**What importing does**
- Each articulation comes in with everything that selects it:
  - several keyswitches at once (VSL Synchron maps use two to four per articulation)
  - a keyswitch whose velocity matters (Spitfire's UACC KS)
  - CCs, program changes and MIDI channels.
- It guesses each one's dynamics: mod wheel (CC1) for longs, legato, tremolo and trills; velocity for shorts. Check the guesses before measuring.
- A Reaticulate file with several instruments asks which one you want. Reaticulate's modifier articulations (such as con sordino on/off) come in unticked, since they change another articulation rather than standing alone.
- **Tick All** / **Untick All** help with big maps, which can have 100+ articulations at about 10 minutes of test audio each.
- Keys an instrument uses as keyswitches are never played as test notes. VSL maps have some inside the playing range, so playing them would switch articulation mid-test.
- There's a new **Library** field per instrument, used in profile names (e.g. "Spitfire BBCSO - Violins 1 - Spiccato").

**What's now saved, for future scripts**
- For every key at every level:
  - when the sound starts and when the attack is heard
  - when the attack finishes (to within ±3 ms; the other times are steadier)
  - the delay of every take, which shows how much round robins differ
  - how loud it is, and how far off it is from its neighbours.
- For each patch: the keys it actually plays, the keys that are too loud or quiet, how delay changes with dynamics, the test settings, and which map it came from.
- `Library.json` indexes every profile with its headline numbers. It lives next to the profiles, in REAPER's resource folder under `Data/Note Fixer`.
- `docs/profile-format.md` describes every field, so later scripts can rely on it.
