# 2026-11-15

Measure Libraries learns articulations from maps, and keeps everything it
finds.

## Route

1. The user asked to import BabylonWaves expression maps. Art Conductor
   doesn't make REAPER maps, so its Cubase and Logic files are what they'll
   have; Reaticulate is REAPER's own. Read the formats from real files
   (cloned to the scratchpad, never committed) and from Reaticulate's
   source for its output syntax.
2. `npvf_maps.lua`. Run over 242 real files: all read. That run showed what
   one switch per articulation couldn't hold: VSL's combinations of up to
   four keyswitches (some in the playing range), Spitfire's UACC KS
   (velocity chooses), outputs on other channels.
3. Articulation choice when fixing rebuilt for combinations (0009).
4. Version 2 profiles, `Library.json`, `docs/profile-format.md` (0010).
   Start, attack and attack end measured in one pass in both Lua and JS.
5. The window: Library, Import Articulations…, a bank chooser, Tick All.

## What looked broken and wasn't

- The attack's end differed by up to 8 ms between Lua and JS: the loudest
  moment of a flat-topped attack wanders. Measured instead as within 1 dB
  of the peak: a median 0.03 ms apart, worst 2.4 where the top ripples.
- A test said D2 wasn't skipped: it measured C3-B3 (keys 60-71), where D2
  isn't. The test was an octave off, not the code.

## Sabotages tried, each caught

Keyswitch keys played as test notes; Cubase's note changer channel read as
the output channel; keyswitch velocity ignored; every key turning off every
other.

## Not done yet

- Studio One, Dorico, Digital Performer and Cakewalk maps.
- Logic's program change output and channel: no file seen had them.
- Still nothing run in REAPER or with a real player.

## Later: Note Fixer for Mac

The user asked for an Apple Silicon app built by GitHub Actions and chose
the full measuring app (0011).

1. Lua 5.4.6 vendored; `npvf_app.lua` (JSON API) and the C bridge, tested
   here with `cc` against the REAPER scripts' Lua (`tests/bridge_test.js`).
   File naming and `Library.json` moved to `npvf_library.lua`, shared.
2. The Swift app, written without a Swift compiler here.
3. The workflow. First run: cancelled at once - "The configuration
   'macos-14-arm64-us-default' is not supported". macos-14 runners have been
   retired since ScaleView's workflow was set up; moved to macos-15.
4. Second run: one compile error - Swift doesn't see CoreAudioKit's
   `AUCocoaUIBase`; the view factory's method is now declared in Swift and
   called through the runtime. (The Lua licence file had also never been
   written: a shell chain stopped at a failed `rm` before it.)
5. Third run: green. The self-test on macos-15 (Swift 6.1.2): Apple's DLS
   synth listed, its state kept (916 bytes) and restored, 25.5 s of test
   rendered in 0.7 s, all 22 notes found, heard 0.8-2.7 ms late (median
   1.7), the restored copy within 0.07 ms, a 0.1 ms shift measured as
   0.110 ms, Stop works, Library.json builds, and the app runs for 8 s
   without quitting. NoteFixer-macOS.zip is 479 KB.
