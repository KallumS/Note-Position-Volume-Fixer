# 2026-11-13

Started from an empty repository: research, then version 1.0.

## Route

1. Researched what exists (docs/research.md). Found nothing that measures per
   key and velocity or touches volume; NTD Engine is the closest product.
2. Built the engine against a made-up library with known answers.
3. Measuring on the whole sound missed quiet notes after loud ones;
   subtracting the projected tail and measuring on each note's harmonics
   fixed most of it (0002).
4. Chords looked fine when the fixed render was checked with the same
   detector, and were 40 ms off against ground truth. Since then every
   accuracy test checks against the library's own numbers (0003).
5. Added learned profiles (0004): within 2 ms everywhere.
6. The page, the browser test, the docs.

## What looked broken and wasn't

- "Spread after" of 17 ms on a re-render: one note not found in the first
  pass stays late and lands in the top 5%. The others are within 10 ms.

## Not done yet

- Not tried in a DAW or with a real library. Most uncertain: where Live
  starts an exported render, whether Live's exported clips carry the tempo,
  reverb baked into samples, legato transitions.
- A profile per articulation, chosen by keyswitch, for parts that switch.
- A Max for Live device that applies a profile in place (research.md §4 C).

## Later the same day: measuring in REAPER

The user asked whether a program could play through their installed
libraries and note down every delay and volume, chose REAPER, and said each
test should start a new track rather than rely on a template.

1. Ported the engine's measuring to Lua (`npvf_measure.lua`) and checked it
   against the engine on the same renders: agreed first time, within 0.5 ms
   and 0.3 dB.
2. `npvf_fix.lua`: several profiles per instrument, each note's articulation
   from its keyswitch, CC, program change or channel; CC1 profiles for long
   notes (0008).
3. The two windows and `npvf_reaper.lua` (0007).
4. A mock REAPER whose *Apply FX* renders the made-up library, and an
   ImGui mock that presses buttons and checks colours. 13 end-to-end checks.
5. Sabotages tried in a scratch copy, each caught: not placing CCs again
   after extending an item; leaving reverb on; no second try after a silent
   render; not following keyswitches.
6. The mock was stricter than REAPER once: reading SWS's `CF_ShellExecute`
   when it isn't installed is nil in REAPER, not an error. Fixed in the mock.
